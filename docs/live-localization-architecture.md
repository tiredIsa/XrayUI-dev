# Переключение языка без перезапуска

Статус: runtime-переключение реализовано. Ниже сохранены архитектурное решение и матрица приёмки;
фактическая реализация и выполненные проверки описаны в следующем разделе.
Основание: текущий WinUI 3 / .NET 10 проект, Windows App SDK 2.0.1, unpackaged-запуск,
471 ресурс в en-US, zh-CN и ru-RU.

## Реализация и проверка

- `Loc` объединяет сервис и совместимый фасад: готовит immutable-каталог из встроенных
  `.resw`, сохраняет выбор, публикует снимок и обновляет привязки. Это те же файлы,
  из которых собирается PRI; отдельной копии переводов нет. Сначала читается en-US,
  затем выбранный язык. Runtime-каталог не зависит от MRT: русский override при запуске
  воспроизводимо заставлял MRT возвращать русские строки вопреки ResourceContext.
- `LanguageResolver` и Windows GetUserPreferredUILanguages отделяют системные предпочтения
  от старого override. При активации окна проверяется системный язык.
- `Localize` заменяет `x:Uid` на всех экранах. Типизированные attached properties обновляют
  только подписи. `LocalizationBindings` хранит callbacks в ConditionalWeakTable владельцев
  и слабые ссылки в реестре. Для DependencyObject scope дополнительно хранится в attached
  property: нативное XAML-дерево может пережить managed-обёртку, поэтому одного CWT
  недостаточно. Время жизни scope отслеживает WinUI вместе с элементом.
  Это замена предлагаемого явного LocalizationScope: повторная привязка свойства заменяет
  callback, новых подписок на глобальные события окон не возникает.
- `LocalizedText` сохраняет ключи и аргументы сообщений диалогов, InfoBar и прогресса;
  внешний текст передаётся без изменения. Задержка активного сервера хранится отдельно
  от задержки выбранного сервера и переводится без новой сетевой проверки.
- SettingsService возвращает свежие снимки, сериализует запись и применяет изменения
  полей относительно исходного снимка через SettingsSnapshotMerge. Существующие писатели
  используют этот общий защищённый путь без массового изменения API. Для языка применяется
  UpdateSettingsAsync. Это осознанное отличие от предложенной полной миграции писателей:
  устаревшая запись порта/подписок больше не перезаписывает неизменённое поле Language.
  Конкурирующие изменения одного и того же поля по-прежнему разрешаются порядком записи.
- Язык сохраняется сразу. Done и применение региона больше не записывают Language.
  Подсказка о перезапуске относится только к региону маршрутизации.

Проверки: 156 unit-тестов, включая таблицу языков, полноту ресурсов/форматов, слияние
снимков и освобождение владельца, захваченного callback. Code-driven WinUI smoke-test
прошёл в Debug и NativeAOT Release: загрузка настоящих XAML-страниц, en/ru/zh,
диалог с несохранённым вводом, пауза и выбранная строка монитора, несохранённые настройки,
команда выбора языка, ошибка записи файла и устаревший писатель настроек.
В тесте прокси не запускается, пользовательские настройки не читаются и не изменяются.

Повторное ревью исправило выполнение устаревших callbacks при замене/удалении во время
Refresh (два регрессионных теста), восстановление скрытой кнопки добавления подписки
при смене языка и прежний язык вложенной подписи в результате импорта.
После сообщения о смешанных языках smoke-test расширен: принудительный GC перед
переключением, проверка переводов TextBlock в реальном дереве страниц, проверка
освобождения отдельного локализованного XAML-элемента. Прежний тест сохранял managed
ссылку на проверяемую подпись и не обнаруживал потерю callbacks у безымянных элементов.

Запуск интеграционной проверки (Windows, без computer-use):

```powershell
dotnet publish XrayUI-dev.csproj -c Release -r win-x64 -p:Platform=x64 -p:BuildingForCI=true -p:LocalizationSmokeTest=true -p:PublishDir=bin/LocalizationSmokeAot/
```

Затем запустить `bin/LocalizationSmokeAot/XrayUI-dev.exe`; он использует отдельную
временную папку, скрытое тестовое окно вне экрана и завершает процесс с кодом 0/1.
Результат записывается в `localization-smoke.txt` рядом с exe. Эта сборка — тестовый
исполняемый файл, не пользовательский клиент. Без свойства LocalizationSmokeTest
диагностический код не включается. Отдельная визуальная проверка и сценарий с реальным
активным TUN в этой сессии не выполнялись; отсутствие сетевых действий обеспечено
отдельным путём локализации и проверено по коду.

## Решение и поведение

Менять локализованные свойства существующих элементов и представлений данных.
Не пересоздавать MainWindow, страницы, ViewModel и сервисы при смене языка.

Пользователь выбирает язык; приложение сохраняет выбор и обновляет подписи сразу.
Дополнительные «Применить», «Готово» и перезапуск для языка не нужны.
На короткое время сохранения недоступен только выбор языка. Прокси продолжает работать.
При ошибке сохранения остаётся предыдущий язык и появляется ошибка с возможностью повторить.

Сохраняются выбранная страница, сервер, фильтры, выделение, прокрутка, фокус,
содержимое полей, раскрытые настройки, режим окна, история и пауза монитора.
Изменение длины текста может вызвать обычную переразметку; абсолютную позицию каждого
пикселя прокрутки после переразметки не обещаем, но список не сбрасываем в начало.

Язык интерфейса и регион маршрутизации — независимые настройки.
Смена языка не вызывает генерацию конфигурации, переподключение, повторные сетевые
проверки, импорт, пересоздание таймеров или изменение системного прокси.
Существующее применение региона через перезапуск остаётся отдельным действием
«Перезапустить для применения региона». Изменение механизма маршрутизации вне этого этапа.

## Что мешает сейчас

| Место | Текущее поведение | Требуемое изменение |
|---|---|---|
| `Helpers/Loc.cs` | Один статический ResourceLoader без уведомлений | Сервис с текущим снимком строк и событием изменения |
| `Helpers/L.cs` | Вычисляемые обёртки над Loc | Сохранить API; он читает актуальный снимок |
| `Helpers/LanguageHelper.cs`, `App.xaml.cs` | Override перед InitializeComponent | Сохранить раннюю инициализацию, добавить явное разрешение языка |
| XAML с `x:Uid` | Применение ресурсов при создании объекта | Явные обновляемые привязки локализованных свойств |
| Конструкторы окон/контролов | Однократное присваивание ToolTip, Name, Title | Ограниченные временем жизни подписки |
| `PersonalizeViewModel` | Язык и регион объединены в ShowRestartHint | Отдельная команда смены языка; hint только для региона |
| `ControlPanelViewModel`, `ServerDetailViewModel` | Часть состояний хранится готовыми строками | Данные состояния отдельно, перевод при отображении |
| `ServerListViewModel`, подписки | Названия служебных групп, ошибки, относительное время | Обновить локализованное представление с сохранением ID |
| `TrafficMonitorViewModel` | Строки record вычисляются, но x:Bind ряда OneTime | Уведомляемые строки и OneWay для переводимых свойств |
| `SettingsService` | Общий изменяемый кэш и сохранение целого объекта | Сериализованные изменения настроек без потери параллельных записей |

Не стоит пересоздавать MainWindow ради текста: его конструктор создаёт XrayService,
TunService и остальные сервисы, а lifecycle окна связан с cleanup, треем и горячими клавишами.
Даже пересоздание только страниц сбросит локальное состояние контролов и обработчики диалогов.

## Компоненты и контракты

Контракты ниже — предлагаемая форма, не готовые исходники.

```csharp
public sealed record LanguageState(
    string? Preference,   // null = как в системе
    string EffectiveTag,  // конкретный поддерживаемый язык
    long Revision);

public interface ILocalizationService
{
    LanguageState Current { get; }
    string GetString(string key);
    string Format(string key, params object?[] arguments);
    event EventHandler<LanguageState> LanguageChanged;
    Task<LanguageChangeResult> ChangeAsync(string? preference,
        CancellationToken cancellationToken = default);
}

public interface ILocalizedPresentation
{
    void RefreshLocalization(); // UI thread; только представление
}
```

`LanguageChangeResult`: Applied, Unchanged, PersistenceFailed, ResourceFailed, Cancelled.
Технические сведения ошибки отдельным полем, не закодированы в тексте результата.
Некорректный тег из команды — ошибка валидации; неизвестный старый тег из settings
обрабатывается по существующей политике миграции в «как в системе».

1. **LocalizationService** — один экземпляр на приложение. Последовательно исполняет
   смену языка, публикует ревизию на DispatcherQueue главного UI-потока.
   Не зависит от XrayService, TunService и управления соединением.
2. **MrtStringCatalog** — единственный адаптер Windows App SDK MRT Core. Готовит
   неизменяемый словарь строк для явного ResourceContext с нужным Language qualifier.
   Ресурсы остаются в `.resw` / `resources.pri`; второго ручного набора переводов нет.
   Каталог читает известные ключи из генерируемого при сборке перечня ресурсов.
3. **SystemLanguageProvider** — читает предпочтения языка интерфейса Windows независимо
   от старого PrimaryLanguageOverride. Для unpackaged-приложения отдельно проверить
   Windows API получения предпочтительных UI-языков; не брать первый язык из
   ApplicationLanguages после применения override и не использовать регион маршрутизации.
4. **Localize** — attached properties для XAML и типизированные привязки для C#.
   Обновляет только зарегистрированные свойства; не обходит визуальное дерево
   рефлексией и не ищет элементы по отображаемому тексту.
5. **LocalizationScope** — владелец подписок конкретного окна, контрола или диалога.
   Регистрация возвращает IDisposable. Для FrameworkElement — Loaded/Unloaded с
   повторной регистрацией без дубликатов; для окна — до Closed; для диалога — try/finally.
6. **Адаптеры представления** — вызывают RefreshLocalization у живых ViewModel/строк.
   Основные ViewModel обновляются и в скрытом состоянии; ленивые страницы при создании
   сразу получают текущие ресурсы. Предметные модели не подписываются на глобальный event.

Loc становится совместимым фасадом сервиса: вызывающий C# код не нужно менять целиком.
Сервис и каталог инициализируются в App до первого чтения L/Loc и до создания UI.
Подготовленные словари доступны для чтения с фоновых потоков; MRT/WinRT объекты и
UI-события остаются на владеющем потоке. Один Format читает один снимок целиком.

## Ресурсы и выбор языка

Хранить Preference отдельно от EffectiveTag: системный русский и явно выбранный
русский дают одинаковые тексты, но разное поведение при следующем изменении Windows.
При изменении только Preference сохранять настройку и уведомлять её представление,
не запускать дорогие обновления строк без изменения EffectiveTag.

Разрешение: явный поддерживаемый язык; иначе первый совместимый язык из предпочтений
Windows; иначе en-US. Для ru и региональных вариантов русского — ru-RU; для английского
— en-US; для китайского учитывать письменность: не считать zh-Hant эквивалентом zh-CN.
Порядок совпадений и резервный язык покрыть тестами. Не полагаться на порядок папок в PRI.

В режиме «как в системе» повторно проверять язык при активации окна и входе в настройки;
проверки дешёвые и ничего не публикуют при неизменном результате. Не нужен таймер.
Системное изменение эффективного языка не переписывает Preference=null.

ResourceContext используется явно: замены одного ResourceLoader недостаточно для
обновления существующего XAML. При обращении к property-key из C# адаптер заменяет
точки на `/`: `Personalize_Theme.Text` → `Personalize_Theme/Text` внутри карты Resources.
Не менять имена существующих ключей ради нового механизма.

При отсутствующем переводе ключа — английское значение и диагностическая запись;
отсутствие ключа и в английском — ошибка валидации каталога до переключения.
Проверять дубликаты без учёта регистра, конфликт bare-key/property-key, параметры формата.

Язык не меняет часовой пояс и региональные форматы Windows. Форматирование чисел и дат
остаётся по системной культуре с явной передачей IFormatProvider в форматтеры.
Не менять глобально CurrentCulture/DefaultThreadCurrentCulture: это может повлиять
на сетевые операции, URL и сериализацию. Подписи единиц берутся из выбранного перевода.
JSON, конфигурация Xray, теги маршрутов и технические идентификаторы используют
исходные значения и invariant formatting.

## Обновление интерфейса

Статический текст постепенно мигрирует с x:Uid на явные attached properties:

```xml
<TextBlock loc:Localize.Text="Personalize_Theme.Text" />
<Button loc:Localize.Content="Dialog_Save"
        loc:Localize.ToolTip="Personalize_ExportTooltip" />
```

Список поддержанных свойств ограничен фактическим UI: Text, Content, Header,
PlaceholderText, Title, Message, ToolTip и AutomationName. MenuFlyoutItem,
InfoBar, ContentDialog и Window требуют собственных типизированных адаптеров.
Для попапов/меню жизненный цикл берётся из владельца или Opening/Closed; нельзя
предполагать, что каждый DependencyObject является FrameworkElement.

На одном свойстве один источник: удалить конкурирующий x:Uid для мигрированного
свойства; Localize не должен перезаписывать пользовательский TextBox.Text,
ItemsSource, SelectedItem, команды или существующий binding состояния.
Для свойств состояния использовать OneWay-привязки к ViewModel, а не Localize.
Новые контроли при регистрации немедленно получают текущую ревизию.

Конкретные обновления:

- MainWindow: заголовок, tooltip кнопок, мини-режим, тексты трея. Меню трея строится
  с актуальными строками при открытии; значок и регистрация горячих клавиш сохраняются.
- ControlPanel: Start/Stop, статус, маршрутизация и найденное обновление пересчитываются
  из IsRunning/IsReapplying и данных версии; никаких Start/Stop-команд при переводе.
- ServerDetail: задержка хранится как статус + миллисекунды; переводятся также пустое
  состояние, подписи цепочки и авторизации. Проверка задержки не повторяется.
- ServerList: служебные группы имеют стабильные ключи (all/favorites/ungrouped/subscription ID).
  Меняется DisplayName; выбор группы и серверов не зависит от перевода. Имена пользователя
  и названия подписок не переводятся. Уведомлять существующие объекты вместо Clear/Add.
- Personalize: служебный пункт «как в системе», названия действий, подсказки и сообщения
  обновляются без LoadFromStore: повторная загрузка затрёт несохранённое оформление.
- Traffic: строки получают уведомления для Route, Context, Details и неизвестного приложения.
  SelectedRow, идентификаторы, фильтры и коллекция сохраняются. Обновить подписи графика
  и открытый tooltip даже на паузе; пауза замораживает данные, а не язык интерфейса.
- LogWindow и CustomRulesWindow: обновляются подписи уже открытых окон. Редактор правил
  сохраняет свой черновик; журнал — буфер, позицию прокрутки и настройки.
- DialogService и отдельный диалог Traffic: подписка действует до закрытия; меняются
  Title, кнопки, подписи, пояснения и validation text. Не закрывать ShowAsync и не терять ввод.
  Операции, завершившиеся после смены языка, форматируют результат текущими ресурсами.

Не считать перевод enum.ToString() решением. Для ошибки/результата, который требуется
перевести повторно, хранить resource key + неизменяемые аргументы + технические детали.
В частности, SubscriptionEntry.LastError сейчас содержит готовый текст: ввести runtime
описатель ошибки и оставить legacy-строку совместимым fallback; не пытаться распознавать
старую ошибку по английскому/русскому содержимому. Старые сохранённые строки не восстановить
до структурированных данных достоверно.

Исторические строки журнала, сырые сообщения Xray, исключения ОС, текст провайдера и
внешний changelog остаются в исходном виде. Они не являются переводимыми подписями UI.
Встроенные меню WinUI, системные файловые диалоги и shell UI могут следовать языку Windows;
проверить отдельно на SDK 2.0.1, не обещать их смену через наш каталог.

## Сохранение, конкурентность и ошибки

1. Проверить значение, подготовить каталог и ресурсы сообщений до изменения состояния.
2. Сериализовать команду; запретить повторный выбор до её завершения. Инициализация
   SelectedLanguageIndex не запускает команду. Отмена допустима до записи настройки.
3. Атомарно сохранить только предпочтение языка через SettingsService.
4. После успешной записи опубликовать готовый снимок, увеличить Revision и синхронно
   обновить живые представления на UI-потоке. После commit не отменять публикацию токеном.
5. Разблокировать выбор. Done сохраняет остальные параметры и не пишет старое значение языка.

Зависимость этапа: безопасное обновление settings.json. Нынешний общий mutable-кэш
позволяет другим SaveSettingsAsync перезаписать результат. Одного семафора вокруг
нового ChangeLanguage недостаточно. Ввести сериализованный UpdateSettingsAsync
с изменением актуального снимка под блокировкой и атомарной заменой файла; перенести
конкурирующих писателей AppSettings на него. Не выдавать наружу изменяемый объект кэша.
Обновление кэша — после успешной записи. Серверные списки не входят в эту миграцию.
Частичный импорт настроек и внешний редактор должны иметь явную политику reload;
обновление языка не должно неявно применять импортированный регион к работающему ядру.

Событие LanguageChanged — уведомление о committed состоянии, не транзакция внешних
обработчиков. Ошибка UI-адаптера не должна убить процесс или отменить настройку на диске:
зафиксировать ошибку, продолжить обновление остальных получателей, предложить повторное
обновление представлений той же ревизии. Это аварийный путь, а не штатная смесь языков;
типизированные адаптеры и полная миграция должны устранить такие ошибки до выпуска.
Не проглатывать ошибки молча и не вызывать App.Restart как автоматическое восстановление.

## Порядок реализации

1. Каталог и LanguageState; тесты языкового разрешения, fallback, ключей, форматов.
   Проверить чтение настоящего PRI с явным языком в отдельном WinUI harness.
2. Сериализованное обновление настроек и согласование всех писателей AppSettings.
   Тест гонки сохранения языка с другими настройками и отказа записи.
3. Localize и LocalizationScope; пилот на обычном TextBlock, Button, ToolTip,
   InfoBar, MenuFlyout и ContentDialog. Проверить повторный Loaded/Unloaded и отсутствие утечек.
4. Миграция всех экранов и динамических представлений. Разделить структурированные
   статусы и готовые строки; обновить подписки, таблицу монитора, мини-режим и трей.
5. Подключить команду языка в Personalize только после миграции. Удалить языковой
   restart hint; оставить отдельный hint региона. Ранний запуск использует тот же resolver.
6. Интеграционные проверки и NativeAOT publish. Не объявлять live-switch готовым
   по одним unit-тестам: прежний сбой ItemsSource показал границу обычной сборки.

## Матрица приёмки

| Сценарий | Ожидаемый результат |
|---|---|
| en → ru → zh → en | Все подписи принадлежат последнему языку; нет повторных обработчиков |
| Явный ru → системный ru | Preference сохранён как null, данные и UI не сброшены |
| Системный неподдерживаемый язык | Английский fallback, без пустых подписей |
| Смена языка при работающем proxy/TUN | Тот же PID ядра, тот же сеанс, нет сетевых команд |
| Несохранённое оформление/правила | Все значения черновиков и раскрытые секции сохранены |
| Монитор live/paused, выбранная строка | Данные/пауза/выбор сохранены; подписи и tooltip переведены |
| Ленивая страница не открывалась | Первое открытие сразу на актуальном языке |
| Открыты журнал и редактор правил | Подписи обоих обновлены, буферы не пересозданы |
| Диалог с вводом или прогрессом | Подписи обновлены; ввод, результат и операция сохранены |
| Закрытие/повторное открытие, 100 смен языка | Число подписчиков не растёт; закрытые окна собираются GC |
| Ошибка записи settings | Старый выбор и язык; понятная ошибка; другие настройки целы |
| Параллельное сохранение настроек | Язык, порт, регион и оформление не перетирают друг друга |
| Язык изменён, регион ожидает применения | Язык действует; региональный hint остаётся |
| Перезапуск процесса | Загружается последний сохранённый выбор |
| Debug и NativeAOT Release | Работают привязки и WinRT-проекция, без reflection-only setters |

Runtime-проверки выполнять через кодовый harness/допустимые тесты и ручную проверку
пользователя. Computer-use не применять без изменения текущего пользовательского ограничения.

## Источники платформенных решений

- [Microsoft: локализация строк и явный ResourceContext](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/mrtcore/localize-strings)
  — `.resw`, применение x:Uid, точки в property-key и `/` при чтении из C#, выбор контекста.
- [Microsoft: x:Uid](https://learn.microsoft.com/en-us/windows/apps/develop/platform/xaml/x-uid-directive)
  — связь идентификатора с ресурсами XAML. Обновление уже созданных элементов
  выполняет предлагаемый слой приложения; автоматическое live-поведение не предполагается.
