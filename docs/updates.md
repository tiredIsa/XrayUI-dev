# Обновления нашего форка

Источник обновлений — `tiredIsa/XrayUI-dev`. Приложение проверяет последний
стабильный GitHub Release при запуске и повторяет проверку после подключения,
если предыдущая попытка не дала результата. Установка требует подтверждения.
Периодической проверки по таймеру и полностью тихой установки пока нет.

## Пользователь

1. Первый раз скачать архив из Releases нашего репозитория и распаковать целиком
   в постоянную доступную для записи папку. `XrayUI.Updater.exe` должен оставаться
   рядом с `XrayUI-dev.exe`. Вариант `-wasdk` содержит Windows App SDK runtime.
2. При появлении отметки на шестерёнке открыть обновление и подтвердить установку.
3. Дождаться скачивания, проверки и перезапуска. Подключение на время установки
   прерывается. Если оно было активно, восстанавливается тот же сервер и режим.
   Если сервер удалён, другой сервер автоматически не выбирается.

Восстановление после обновления не зависит от настройки автоподключения при входе
в Windows. Отключённое приложение остаётся отключённым. Для восстановления TUN
updater сохраняет имеющиеся повышенные права; если их нет, приложение запросит
UAC. Отмена не приводит к переключению на обычный прокси. Обычный запуск без
аргумента восстановления не повторяет этот сеанс.

При отмене UAC для записи файлов updater запускает старую версию с тем же
запросом восстановления. Автоматического отката при частичной ошибке копирования
пока нет. Лог: `%LocalAppData%\XrayUI\Updates\updater.log`.

Старая авторская сборка проверяет авторский репозиторий: для перехода на наш канал
нужно один раз установить нашу сборку вручную. Старый updater не поддерживает
новые аргументы восстановления; функция работает, когда установлен updater
из нашего нового комплекта. Сборки `0.0.0-dev` обновления не проверяют.

## Выпуск версии

1. В `changelog.json` перенести подготовленные `unreleased.en` и `unreleased.ru`
   в новый объект массива `versions`, добавив `version` с номером выпуска.
   Номер должен совпадать с тегом без префикса `v`, например `2.1.0`.
   Перевод `zh` необязателен; при его отсутствии показывается английский.
2. Закоммитить изменения и отправить тег выбранной версии в наш репозиторий.
3. Workflow `release` проверит описания, соберёт x64/ARM64 и оба варианта runtime,
   приложит архивы, SHA-256 и `changelog.json` к GitHub Release.

Релизные описания берутся из файла самого релиза, чужой сайт не используется.
Номера выпусков должны возрастать относительно уже разданных сборок.
Ручной запуск workflow на ветке создаёт только артефакты для проверки.

## Проверено при разработке

- .NET-тесты аргументов восстановления: оба режима, точный ID с Unicode и
  специальными символами, ошибочные и неоднозначные аргументы.
- Выбор русских описаний и переход на английский при отсутствии перевода.
- Rust-тест передачи только одного разрешённого аргумента восстановления.
- Настоящий updater в отдельной тестовой папке: замена файлов и запуск тестового
  приложения с TUN, proxy и без подключения. Реальные маршруты и UAC эта проверка
  не затрагивает.

Полный сетевой сценарий требует двух опубликованных версий и тестовой Windows
с рабочим сервером: подключиться, обновиться и проверить восстановление трафика.
